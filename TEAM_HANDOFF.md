Работает полный цикл: человек объясняет тему → ИИ-ученик отвечает → формируется тетрадь → ученик сдаёт вопросы → приложение считает результат и показывает, что повторить. История сохраняется без входа, отдельно для каждого браузера. Голосовой ввод есть; озвучки ответов и голосового разговора пока нет.

## Обновление интерфейса

История переехала в открывающуюся панель слева и доступна внутри занятия. На узком экране используется выдвижная панель поверх страницы. Темы выбираются из выпадающего списка; чат различает сообщения пользователя и ученика и показывает время. Enter отправляет, Shift+Enter добавляет строку. Микрофон и AI-логика не менялись. Safari-проверка выбора темы, создания занятия, обновления истории и переходов выполнена; клавиатурная отправка требует ручной проверки из-за ограничения фокуса инструмента автоматизации.

## 1. Что показываем на демо

1. Открыть сайт и выбрать **Project stakeholders · Demo**.
2. Начать занятие и объяснить тему текстом или через микрофон.
3. Получить короткий ответ ученика и записи тетради со ссылками на своё объяснение.
4. Нажать **Start student exam**, когда тетрадь актуальна.
5. Увидеть балл из трёх, ответы, обоснования и записи, на которые опирался ученик.
6. Дообъяснить тему, обновить тетрадь и пересдать. Сравнить последние две попытки: баллы, улучшенные и ухудшенные ответы, новые цитируемые записи.
7. Скачать TXT или JSON через **Download this session**: сообщения, тетрадь и все сохранённые попытки. Импорта обратно и восстановления доступа через файл нет.
8. Вернуться на главную и открыть занятие из истории в том же браузере.

В демонстрационном пакете **четыре темы и двенадцать оригинальных вопросов**: stakeholders, risks, change control и Scrum. Это не официальный экзамен PMP и не прогноз результата сертификации. Успешное прохождение темы в приложении означает три правильных ответа из трёх.

## 3. Вход и владение историей

Последнее решение владельца: **убрать вход и оставить историю без аккаунта**.

- В интерфейсе нет Email, Google или admin-входа. `/login` и `/auth/callback` ведут на главную.
- `src/lib/anon-id.ts` хранит случайный UUID в localStorage. API получает его в `x-anonymous-id`.
- `src/lib/api.ts` отправляет запросы с `credentials: omit` и удаляет заголовок авторизации. Старая cookie общего демоаккаунта не должна подмешивать его историю.
- Сервер проверяет владельца при чтении и записи. Чужая сессия не должна быть доступна по одному URL.
- Старые аккаунтные записи и код авторизации оставлены для совместимости. Они не перенесены всем гостям. В production `DEMO_AUTH_ENABLED=false`.
- Очистка данных сайта, другой браузер/устройство или завершение приватного сеанса могут лишить доступа к истории. UUID фактически является ключом доступа: его нельзя публиковать.
- История с `localhost` автоматически не появляется на production-домене: это разные браузерные хранилища.

Не возвращать авторизацию только потому, что её описание осталось в старых частях проектного плана.

## 4. Архитектура и точки входа

Стек: Node.js 24, Next.js 16, React 19, TypeScript, PostgreSQL через `pg`, Vitest. Версии установки фиксируются `package-lock.json`.

| Путь | Ответственность |
| --- | --- |
| `src/components/session-workspace.tsx` | Сценарий занятия, сообщения, запуск тетради и экзамена |
| `src/components/learning-panel.tsx`, `exam-review.tsx` | Тетрадь, состояние обучения и просмотр попытки |
| `src/components/session-history.tsx`, `dashboard.tsx` | История и главный экран |
| `src/components/voice-input.tsx`, `src/lib/speech-recognition.ts` | Микрофон, жизненный цикл распознавания, черновик |
| `src/lib/api.ts`, `anon-id.ts`, `types.ts` | Браузерные запросы, идентичность и общие контракты |
| `src/app/api/` | Тонкие HTTP-обёртки, валидация и проверка владельца |
| `src/server/learning.ts`, `student-reply.ts` | Оркестрация обучения и генерации реплики |
| `src/server/repositories/` | Хранение данных, блокировки, кеширование, резервирование расходов |
| `src/server/database-config.ts`, `db.ts` | Подключение PostgreSQL и проверяемый TLS |
| `src/ai/client.ts`, `config.ts` | Единственная граница вызова OpenAI, модель и лимиты |
| `src/ai/student.ts`, `notebook.ts`, `examinee.ts`, `schemas.ts` | Подготовка входов, структурированные ответы, проверки |
| `src/ai/debrief.ts`, `src/server/grading.ts` | Детерминированный разбор и оценивание |
| `prompts/` | Отдельные файлы промптов |
| `content/exams/pmp/` | Темы, идеи и вопросы; факты экзамена не добавлять в движок |
| `db/schema.sql` | Таблицы, ограничения, индексы и RLS |

Основной поток API:

```text
POST /api/sessions { topicId }
  → POST /api/sessions/:id/messages { text }       сохраняет объяснение
  → POST /api/sessions/:id/reply { messageId }     ответ ученика
  → POST /api/sessions/:id/notebook {}             тетрадь
  → POST /api/sessions/:id/exam {}                 экзамен и оценка
  → GET  /api/sessions/:id/debrief                 сохранённый разбор

GET /api/sessions?offset=0                        история, по 20 записей
GET /api/sessions/:id                             полное состояние занятия
GET /api/sessions/[id]/export                    JSON всех сохранённых данных занятия; только владелец
GET /api/topics                                  темы и прогресс
GET /api/progress                                серия дней и пробелы
```

Точные типы ответов — в `src/lib/types.ts`, поведение маршрутов — в `src/app/api/`. Сообщения возвращаются JSON, не потоком. Запросы записи требуют same-origin JSON и проверки владельца. GET не должен запускать платную генерацию.

## 5. OpenAI и общий бюджет

Используется `gpt-6-luna`. Конфигурация разрешает только эту учтённую модель. Максимум бюджета приложения — **$4 на всех пользователей**, а не на человека, день или запуск сервера.

- Секретный `OPENAI_API_KEY` используется только на сервере.
- Единственная точка HTTP-вызова модели — `src/ai/client.ts`; новые провайдерные вызовы не рассыпать по маршрутам.
- Перед генерацией PostgreSQL атомарно резервирует консервативную сумму в `ai_usage`. Параллельные процессы используют один остаток.
- Резерв остаётся израсходованным при коротком ответе или ошибке сети. Это оценка сверху, а не банковский баланс и не фактический счёт OpenAI.
- `ai_usage` нельзя очищать при перезапуске, миграции или удалении занятия. Другие приложения с тем же OpenAI-ключом этим лимитом не ограничены.
- Нет автоматических повторов провайдера, web tools или автоматического перехода на дорогую модель. Reasoning отключён.
- Лимиты ответа: student — 256 токенов, notebook — 1024, exam — 768; общий потолок клиента — 1536. Вход ограничен 6000 посчитанных токенов.
- Объяснение ограничено 4000 символами. Чат использует до 12 последних сообщений в пределах 12000 символов. Извлечение тетради ограничено 24 объяснениями/12000 символов; превышение возвращает ошибку, не стирая старую тетрадь.
- Готовый ответ переиспользуется; тетрадь и экзамен кешируются по версии объяснений. Новое объяснение делает старые результаты неактуальными. Короткие блокировки и трёхсекундные задержки между новыми заданиями ограничивают дублирующую работу.

**Локальный AI после переноса выключен бюджетом `0`.** Нельзя включать второй независимый лимит $4 поверх старой локальной базы. Новая платная инстанция должна использовать тот же долговечный облачный счётчик либо отдельно согласованный бюджет.

## 7. Насколько доказана работа по тетради

Гарантируется кодом: записи являются цитатами пользователя; экзаменационный запрос не содержит ключей и чата; пустая тетрадь даёт ноль без запроса модели; догадки и несуществующие ссылки не засчитываются.

**Проверки существования ссылки недостаточно, чтобы доказать смысловую связь ответа с цитатой.** Такая проверка в рабочем сервере пока не реализована. Модель сохраняет знания из обучения; отсутствие web tools не означает их отсутствия.

Живой эксперимент 14 ноября: **12 из 13 прогонов соответствовали заранее заданному ожиданию**.

| Условие | Результат |
| --- | --- |
| Постороннее объяснение, 3 прогона | Пустая тетрадь, 0/3; экзаменационная модель не вызывалась |
| Непустая, но недостаточная тетрадь, 3 прогона | Отказы, 0/3 |
| Только одна нужная идея, 3 прогона | 1/3 |
| Ошибочное объяснение, 3 прогона | Дважды воспроизведена ошибка, один раз отказ; всегда 0/3 |
| Полный материал, 1 прогон | 3/3 |

Это малая выборка на одной теме и английском языке, не доказательство полной изоляции знаний. Воспроизведение преподанной ошибки нестабильно. Нужны русскоязычные случаи, переформулировки, конфликтующие записи и инструкции внутри объяснения.

Полный ESLint ранее находил ошибки React hooks в старых компонентах авторизации; успешная выборочная проверка не равна чистому общему lint. Микрофон тестируется поддельным recognizer; разрешения и качество реального устройства проверяются вручную.

```sh
npm ci

npm run dev
```

Нужны Node.js 24 и PostgreSQL 15+. Локальный setup сохраняет существующий `.env.local`, использует `.data/postgres` и порт 55433. Для своей базы следовать разделу запуска в README. Не перезаписывать имеющийся `.env.local` командами загрузки окружения Vercel.

```sh
npm run typecheck
npm test
npm run lint
npm run build
```

Без `TEST_DATABASE_URL` часть интеграционных тестов пропускается. Для полного набора использовать **отдельную одноразовую тестовую базу**, не production. Тесты с моками провайдера не расходуют OpenAI. `node scripts/eval-notebook-grounding.mjs` только показывает план; добавление `--live` создаёт занятия на production и расходует общий бюджет — это не обычный unit-тест.

## 9. Ближайшие задачи

1. **Контент:** расширить пакет PMP, проверить материал и источники. Не копировать платные банки вопросов.
2. **ИИ:** усилить проверку связи ответа с цитатой и расширить эксперимент. Сохранить принцип «учится у человека», не превращать ученика в преподавателя.
3. **Продукт:** согласовать и подключить тему дня; сейчас рекомендация не работает, хотя функция выбора уже есть.
4. **Голос:** владелец хочет естественные ответы, но ищет решение без дополнительных платежей/обязательной карты. Провайдер не выбран, интеграция не начата. Не выдавать обсуждённые тарифы за подключённую функцию. Любой платный голос требует отдельного учёта расходов; существующий OpenAI guard автоматически чужую API не покрывает.
5. **Качество:** проверить мобильный сценарий, реальные микрофоны и полный lint; перед демо пройти живой цикл и убедиться, что повторное открытие не тратит бюджет.
6. **Питч:** подготовить деку и подтверждённые рыночные данные; в репозитории остаются TODO по дедлайну и распределению ролей.
